1 접속할 URL을 바로 확인

Host·Path·외부 포트를 합쳐 표시합니다. AWS 예시는 :30880을 포함하고, IBM은 기본 HTTP 포트 80이므로 생략합니다.

2 hosts에 넣을 IP는 상세 팝업에서

노드 IP 또는 LB IP를 선택하면 IP Host 한 줄을 복사할 수 있습니다. 실제 구현 시 주소를 조회해야 하며, 조회되지 않으면 임의 IP를 표시하지 않는 구상입니다.

목록의 기존 상태·관리 기능은 유지하는 전제입니다. 시안에서는 접속 정보 변경에 필요한 항목만 표시했습니다.

변경 영역

접속을 허용할 사용자의 공인 IP 대역입니다. 노드/LB의 목적지 IP가 아닙니다.

로컬 테스트 시 이 Host를 IBM LB IP에 매핑합니다.

EXPECTED CONNECTION URL · 예시http://nginx.ibm.test/

IBM Managed LB · 외부 HTTP 80 → Ingress → Service 80

HTTP 연결은 암호화되지 않습니다. 이 시안에는 Protocol/TLS 입력을 추가하지 않습니다.

Ingress 관련 입력을 숨깁니다. 이 설정으로는 Ingress 접속 URL을 만들지 않습니다.

실제 검사·배포는 수행하지 않습니다.

입력 순서만 자연스럽게

  1. Enable Ingress
  2. Allowed IPv4 CIDR
  3. Worker Security Group 허용
  4. Host
  5. Path
  6. Ingress Class · 읽기 전용

IBM도 Ingress를 사용합니다

IBM LB가 받은 요청을 기존 IBM 관리형 Ingress Controller가 앱의 Service로 전달합니다. 이 화면에는 워커의 30880 포트 허용 항목을 표시하지 않습니다.

CIDR 위치 변경 시안입니다. 기존 배포 정책·인증서 관리 기능을 새로 변경하는 제안은 아닙니다.

IP는 문서용 예약 주소, 도메인은 테스트용 이름입니다. 실제 접근 허용 범위와 배포 값으로 사용하지 마세요.
